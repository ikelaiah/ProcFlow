# ProcFlow v2.0.0 — Trustworthy SQL Analysis Contract

## Contract

v2 formalises ProcFlow's conservative static-analysis contract: source-derived
facts need static evidence; dynamic, ambiguous, malformed, and unsupported
SQL stays visible rather than becoming invented structure. See the
[v2 accuracy contract](../V2_ACCURACY_CONTRACT.md).

## Qualification

The checked-in cross-dialect adversarial matrix covers 15 synthetic cases and
56 semantic assertions: 41 required and 15 forbidden. All assertions pass.

| Dialect | Cases | Assertions |
| --- | ---: | ---: |
| T-SQL | 7 | 27 |
| PL/pgSQL | 4 | 13 |
| DB2 SQL PL | 3 | 12 |
| SQLite | 1 | 4 |

The fixture-only `dialectAdversarialSemanticAssertionRate` is `1.0`. It catches
the defect class that token attribution alone cannot: a relationship omitted or
invented while syntactic accounting remains complete.

## Compatibility

Workspace schema 2 supports deterministic migration of older snapshots and
non-destructively rejects newer schemas. Existing graph edge kinds,
provenance, diagnostics, confidence formula, and export semantics remain
compatible; v2 adds qualification evidence rather than a gratuitous format
break.

## Privacy

The self-contained runtime remains local-first: no backend, telemetry, SQL
upload, database connection, or execution. Hostile export text remains escaped
and browser storage remains opt-in.

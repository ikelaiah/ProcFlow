# ProcFlow v2.2.0 — Arrange and save the ERD

Released as the `v2.2.0` layout milestone. The ERD page can now arrange a whole
estate automatically and remember the result.

## Highlights

- **Auto arrange.** A deterministic layered layout places referenced tables to
  the left of referencing tables, orders each layer with bounded barycenter
  crossing reduction, and breaks cycles and self-references deterministically
  by declaration order. Views are placed downstream of the tables referenced in
  their `FROM`/`JOIN` clause — declared evidence only, never an inferred edge.
- **Band wrapping.** Wide and tall estates wrap into bands: an 800-table FK
  chain lays out as a 3,192 × 16,208 grid instead of a 217,000-pixel line, and
  a 799-leaf fan becomes a 3,192 × 11,480 grid instead of a 128,000-pixel
  column. Layout for 800 tables takes ~53 ms in the chain case and ~5 ms in the
  fan case, with zero overlaps at uniform card sizes.
- **Save the layout.**
  - **Save / Restore / Forget** store a versioned layout in this browser
    (opt-in only, under its own key; nothing is written without an explicit
    action).
  - **Export / Import** produce and read a `procflow-erd-layout` JSON file
    carrying a schema fingerprint. On a changed schema, matching entities keep
    their positions and unmatched entities are appended below the stage rather
    than overlapped or dropped.
- **Persistent free positioning.** The canvas now uses absolute positions, so a
  dragged card keeps its place across re-parsing, edits, Compact mode, and
  layout saves. **Reset** returns to declaration order.
- **Layout menu** groups Auto arrange, Reset, browser save/restore/forget, and
  file export/import, with a status line for each action.

## Accuracy and limits

- Auto arrange is a deterministic near-optimal layout, not a minimum-crossing
  guarantee; arbitrary schema graphs can still cross. Crossing reduction is
  bounded (four barycenter passes) so results are reproducible.
- View sources are parsed from the view body as a layout hint. A view whose
  body cannot be read is simply placed in the downstream band; no relationship
  edge is created from view text.
- Saved layouts are keyed by entity id and a schema fingerprint. Renamed
  entities are treated as new and appended; removed entities are pruned.
- Layouts are UI state: they are not part of the SQL analysis and do not affect
  the accuracy contract, Mermaid export, or workspace snapshots.

## Verification

The final local verification recorded for this release includes:

- `npm run typecheck`, `npm run build`, `npm run test:file`, and
  `npm run metrics` passing;
- golden browser assertions on `tests/index.html` passing (220/220), including
  the v2.2.0 layout fixtures: determinism, no overlaps, parent-before-child
  columns, view-source placement, layout-file round-trip and rejection cases,
  and a 300-table overlap check (29/29 schema suite);
- 31/31 UI interaction checks and the hostile-input security suite passing;
- ERD smoke checks: 800-table chain auto-arranges to a banded grid (3,232 ×
  13,568 page stage, zero page errors), Fit at 5%, drag deltas correct at 66%
  zoom, save → auto-arrange → restore returning the dragged position;
- runtime archive structure and local-file startup smoke passing
  (`procflow-v2.2.0.zip`).

## Upgrade and distribution

The runtime is self-contained. Use `npm run package:runtime` to produce the
versioned ZIP and verify `.release/SHA256SUMS.txt` before distributing it.
Workspaces and layouts saved by v2.1.0 remain readable; layout files are
versioned independently of the workspace schema.

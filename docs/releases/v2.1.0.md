# ProcFlow v2.1.0 — Entity relationship diagrams

Released as the `v2.1.0` ERD milestone. ProcFlow now visualises SQL procedures
and declared schema relationships in one local-only package.

## Highlights

- **New ERD page (`erd.html`).** Paste or import `CREATE TABLE` / `ALTER TABLE`
  DDL and review declared tables, views, columns, primary/unique/foreign keys,
  and composite-key grouping. Supported dialects: T-SQL, PostgreSQL, DB2, and
  SQLite. Raw column type text is preserved per dialect; entity, column, and
  key spans point back into the source DDL.
- **Declared constraints only.** Relationship edges come exclusively from
  declared `FOREIGN KEY` constraints. Unqualified targets resolve by name only
  with a labelled warning; ambiguous or missing targets stay explicit
  (ambiguous is not drawn, missing becomes an external entity).
- **Mermaid `erDiagram` export.** Deterministic output with cardinality
  (`||--o{`, `o|--o{`, `||--||`), optionality from FK nullability, `PK`/`FK`/`UK`
  markers, and `%%` provenance comments carrying original names and raw types.
- **Estate navigation.** Drag the canvas to pan, drag tables to declutter
  relationships, click a table for the FK inspector (column mapping,
  cardinality, optionality, constraint name), use Find to jump between
  matches, and use smooth wheel zoom or Fit for the whole estate. Boxes
  compact automatically above 150 entities, and auto-draw pauses above the
  shared 100,000-character large-input threshold.
- **Shared UI polish.** A draggable editor/diagram divider on both pages and a
  clear Flowchart/ERD page switcher with an active state.
- **Fixes.** View cards were hidden by a collision with the global `.view`
  convention; Fit zoomed out indefinitely on large estates because CSS zoom
  reflowed the grid; ERD card selection was broken under real mouse input by
  pointer capture retargeting the click.

## Accuracy and limits

- Declared constraints only. No relationship is inferred from query text, and
  disabled or unenforced constraints are not distinguished from enforced ones
  in the DDL text.
- `ALTER TABLE` before its `CREATE TABLE` is reported and not back-applied;
  CTAS tables and views without a declared column list report unknown columns.
- Layout is manually adjustable; table positions are session-only and are not
  written to the workspace.

## Verification

The final local verification recorded for this release includes:

- `npm run typecheck`, `npm run build`, `npm run test:file`, and
  `npm run metrics` passing;
- golden browser assertions on `tests/index.html` passing (220/220), including
  the new v2.1.0 schema suite (22/22, 7/7 Mermaid assertions, plus a 300-table
  bulk estate fixture);
- 31/31 UI interaction checks and the hostile-input security suite passing;
- ERD smoke checks: an 800-table / 175 KB estate parses in ~90 ms with zero
  diagnostics, 800 relationships, auto-compact, Find, FK selection, and Fit at
  4% with the selection ring visible;
- runtime archive structure and local-file startup smoke passing
  (`procflow-v2.1.0.zip`).

## Upgrade and distribution

The runtime is self-contained. Use `npm run package:runtime` to produce the
versioned ZIP and verify `.release/SHA256SUMS.txt` before distributing it.
Workspaces saved by v2.0.0 remain compatible.

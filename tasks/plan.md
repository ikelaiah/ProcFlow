# Implementation Plan: ProcFlow v2.0.0 qualification

## Overview

Complete the bounded v2 release blockers from the current v1.14.1 baseline:
add a checked-in cross-dialect semantic qualification matrix and metric, make
workspace imports reject unsupported future schemas without mutation, and then
promote only documentation and version metadata backed by passing evidence.

## Architecture decisions

- Keep adversarial cases declarative in a dedicated TypeScript fixture file;
  a small evaluator will run the actual analyser, graph, estate, catalogue, and
  column-lineage code and publish counted results for the metrics page.
- Treat unknown future workspace schemas as an explicit parse error. This is
  safer than normalising a payload while discarding fields.
- Preserve historical v1 metrics and release records. The v2 snapshot is a new,
  deterministic checked-in file generated by the existing metrics workflow.

## Task list

### Phase 1: Compatibility foundation

- [x] Add a failing future-schema workspace fixture and result reporting.
- [x] Reject future workspace versions without migration or storage mutation.
- [x] Verify the workspace suite and file smoke.

### Phase 2: Semantic qualification matrix

- [x] Define typed required/forbidden semantic assertions and representative

- [x] Add a matrix evaluator with diagnostic, provenance, graph, estate,
  catalogue, and column-opacity assertions plus actionable failure details.
- [x] Wire the evaluator into browser test and metrics bootstraps.

### Checkpoint: Qualification

- [x] Matrix passes in the built browser suite.
- [x] Per-dialect and required/forbidden counts are published.

### Phase 3: Release convergence

- [ ] Add the v2 metric to generation/verification and write its snapshot.
- [ ] Re-audit and finalise the accuracy contract and release-facing documents.
- [ ] Update active versions and generated runtime files only after the
  qualification gate is green.
- [ ] Run all local release gates, then perform authorised branch/PR/CI/release
  work if no material blocker remains.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Existing parser does not support a proposed semantic fact | Assert conservative opacity or fix only a minimal reproduced defect; never weaken a false-positive prohibition. |
| Metric bootstrap ordering hides matrix results | Load matrix after all analyser dependencies and before the metrics evaluator; verify browser output. |
| Future workspace input gets changed through import handling | Reject it during parsing before the UI can restore or persist it; add deterministic parser and browser-storage tests. |
